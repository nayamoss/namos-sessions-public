### Production is stale beyond the agenda

### Why production is stale

There is **no deploy job in CI**. `.github/workflows/ci.yml` runs tests only — it has no
Cloudflare step, no `wrangler deploy`, nothing. Production is deployed only when a human
runs `npm run deploy` (→ `scripts/deploy-cloudflare.mjs`) by hand, and nobody has since
before the drag-and-drop work landed.

This is the already-open issue #196 ("main never auto-deploys"). It is not a separate
infrastructure nit — it is the direct cause of the feature appearing not to exist.

## Bug found and fixed

`src/pages/program/AgendaMoveControl.tsx` seeded room and start time with `useState(...)`, which
only reads its argument on first render. The card stays mounted while you work, so after moving a
session by drag, reopening the Move popover still showed the **old** room and time — and confirming
would silently move the session back where it came from.

Fixed by re-seeding room/time (and clearing any stale error) each time the popover opens.

Verified in the browser: created a session in Main Hall 9:00 AM, dragged it to Studio B 1:00 PM,
reopened Move → popover reads Studio B / 01:00 PM. Before the fix it read Main Hall / 09:00 AM.

**This fix is uncommitted.** The working tree is on `fix/wrangler-vars-placeholders` with 42 files
modified by a concurrent session, so committing would sweep in someone else's in-flight work.

## Non-findings (ruled out, so nobody re-investigates)

- **"Agenda item not found for this event"** (`convex/agenda.ts:225`) is not a bug. The
  `agenda_items_audit` table shows a QA harness deleted the Wizard QA Summit fixture's sessions at
  09:45:57 and 09:47:08 ET — seconds after a successful move — and wiped the event's rooms too. The
  backend guard correctly refused to write to deleted rows.
- **There is a public schedule surface**, it just isn't called "Schedule": `/embed/:embedId`
  renders all six embed views including `schedule_grid` (day-by-day timetable, rooms as columns)
  and `schedule_itinerary`, and `/e/:eventSlug/:feed` serves hosted `agenda | sessions | itinerary
  | speakers` feeds. You reach it via CMS → Embeds. That is a naming/discoverability gap, not a
  missing feature.
